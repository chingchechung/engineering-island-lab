# Engineering Island Lab — Phase 2 教師驗收修正指示

Repository:
https://github.com/chingchechung/engineering-island-lab

目前 Phase 2 已建立 Draft PR #2，教師已在 Windows 11 實際檢查並提出以下八項修正要求。

**請在原本的 `feature/phase-2-full-archipelago` 分支上繼續修改，更新同一個 Draft PR #2，不要另建 PR，也不要進入 Phase 3。**

請先閱讀 AGENTS.md、Plan.md、PROJECT_SPEC.md、PHASE_2_ACCEPTANCE.md，以及目前的實際程式與測試。

## 1. 放大島嶼名稱標籤

目前 S01–S15 的島名太小，難以辨識。

要求：

- 明顯放大 Sxx 編號及中文島名。
- 桌面全域總覽建議 Sxx 約 16–18 px、島名約 13–15 px，可依實際畫面調整。
- 放大聚焦時可再提高字級。
- 手機窄畫面也不能退回到難以閱讀的 8–9 px。
- 維持文字對比、背景及適當留白。
- 15 島總覽時不得出現嚴重的標籤互相遮擋。
- 若標籤變大影響構圖，請同時改善群島布局與 label collision avoidance。

**驗收重點：1366×768 的 12 島總覽，Sxx 與島名必須容易閱讀。**

## 2. 大幅增加島嶼的靜態裝飾

目前部分島嶼雖有不同地形，但表面仍顯得空曠。

請依照每座島的主題，豐富場景內容。

可加入：

- 不同大小及顏色的花草
- 草叢、灌木、樹木
- 小石頭、大岩塊、岩石群
- 木桶、木箱、路燈、木製招牌
- 小溪、池塘、瀑布、岸邊浪花
- 冰晶、珊瑚、糖果、火山岩等主題裝飾

不是要求每座島都放所有物件，而是讓各島有不同且豐富的場景。

特別希望增加類似早期參考圖片中自然懸崖、瀑布與岩層的立體細節。

限制：

- 保持色彩豐富、自然、可愛的 3D 微型模型風格。
- 不要只用大量相同的小球或方塊填滿地面。
- 裝飾不能遮住 Lecture 小屋及 NPC。
- 不影響柵欄、鎖牌、島名與點擊目標。
- 使用共用 Geometry / Material、InstancedMesh 等方法控制 Draw Calls。
- 靜態場景不需要增加物理或互動功能。
- Quiz 和 Video-only 模式都要呈現相同的完整裝飾。

## 3. NPC 改成自主走動

目前 NPC 固定站在原本座標。

請改成 NPC 能夠在島上的小範圍內自主漫遊。

行為要求：

- 每位 NPC 有自己的活動中心及有限活動半徑，建議先以約 1–2 個遊戲單位為初始設定。
- 自動選擇附近的安全位置，緩慢走動。
- 偶爾停下來、轉身、等待，再繼續走動。
- 移動速度不要太快，不要讓學生難以點擊。
- NPC 必須待在島上，不得走進海裡、建築、岩壁或島外。
- 不要與其他 NPC 大量重疊。
- NPC 的 Q01–Q05 頭頂標籤必須跟隨角色移動。
- 衣服與帽子的編號辨識保留。
- 點擊 NPC 模型或頭頂標籤後，NPC 立即停止移動並開啟目前的題目 Demo Modal。
- Modal 關閉後，NPC 可以恢復自主漫遊。
- Hover 不必讓 NPC 停止，但可以加上互動高亮效果。
- 移動中仍應維持正確的 Raycasting 和點擊功能。

請特別注意現有 Static Batching / Optimization：

**移動中的 NPC 及其子模型不能被合併到不會移動的世界座標幾何中。**

未來 Phase 4 整合正式 Quiz 時，也要能直接沿用這套移動和暫停機制。

Video-only 模式仍然完全不建立 NPC。

本次只修改 NPC 的視覺動畫與互動，不實作正式 Quiz 答案判斷。

## 4. 大幅精簡網頁頂部

教師希望整個網頁的可視範圍盡可能用來顯示 3D 群島。

目前：

- 頁面上方有 Engineering Island Lab。
- 下方又有「數位電子學」大標題。
- 還有其他裝飾性副標題。

請修改為：

- 網頁最上方直接顯示 `course-config.json` 的 `courseTitle`。
- 目前預設為「數位電子學」。
- 不要再重複顯示第二個大型課程名稱。
- 移除或大幅縮小不必要的副標題、裝飾性英文及大面積空白。
- 將 Header 改為精簡的單列工具列。
- 保留必要的說明與控制功能，但不可佔用大量 3D 畫面。

這必須支援其他課程名稱，不得直接寫死「數位電子學」。

瀏覽器頁籤 title 可以保留 Engineering Island Lab 作為專案識別，但網頁主要標題應直接使用課程名稱。

## 5. 左下角改成單元選擇功能

目前左下角的「探索 S01」不符合教師希望的操作方式。

請改為：

- 左下角使用精簡的島嶼選擇下拉選單。
- 內容由 `totalUnits` 自動產生。
- 提供「群島總覽」、「中央學院」，以及 S01–Sxx。
- 選擇某座島後，直接平滑聚焦。
- 未開放的島仍可選來欣賞地貌，但顯示鎖定標記且不可開啟課程內容。
- 目前選取島嶼要與下拉選單同步。
- 不必保留原本大量描述文字的探索卡片。

由於右上方已經有「前往小島」選單，請整合這兩個重複功能，正式頁面只保留**一個**清楚的單元導覽控制，優先放在左下角。

## 6. 移除右下角過多控制與資訊

目前右下角包含：

- 單元數
- 開放數
- 角色數
- Quiz / Video-only 等 Demo 控制

這些是測試功能，不應長期占據群島畫面。

請：

- 從一般展示版面移除右下角 Demo 設定區。
- 正式網站不提供讓學生任意修改課程模式、開放進度、題目數或總單元數的控制。
- 以 JSON 作為正式設定來源。
- 保留開發者測試能力，但不要在一般 Demo 畫面顯示一大片控制面板。
- 可改為只在 Vite 開發模式使用受控 query parameters，或另外提供明確開啟的測試面板。
- 所有 Demo 設定都不得在 production build 生效。

建議可測試：

`?demo=1&units=12&open=4&questions=4`

以及：

`?demo=1&units=15&open=15&questions=5`

必要時增加僅開發模式有效的 mode 參數。

請保留縮放、返回總覽及單元導覽等真正提供給學生使用的控制。

## 7. 群島改成明確放射狀布局

目前使用幾條長鏈，例如：

Academy → S01 → S02 → S03

這讓整體群島在總覽時偏向水平延伸，中央學院沒有明顯的中心感。

請重新規劃布局：

- 中央學院是群島的視覺中心。
- S01–S12 分布在中央周圍的多個方向。
- 使用 **Radial Hub-and-Spoke Layout**。
- 建議至少六條主幹橋由中央學院向不同方向延伸。
- 其餘島嶼透過短支線接到附近的主幹島。
- 避免連續串接三座以上形成長條狀島鏈。
- 橋樑要像從中央學院向外放射的交通網路。
- 不必每座島都直接與中央學院相連，以免 15 條橋在主島附近過度擁擠。
- 但從總覽應明顯感受到中央向外放射，而不是一條水平線。
- 優先保留既有 S01 的地貌與橋樑外觀；若需調整島的位置可以接受。
- 確保橋樑不交叉、不穿過島體，兩端正確接上海岸。
- 未開放島橋口的柵欄及鎖牌規則保持不變。
- 12 島及 15 島都要自動有良好構圖。
- 返回總覽時所有島都在可視範圍。

請同時調整 OrthographicCamera 的 fit 與 zoom 範圍，不可因為布局改變而讓單島聚焦變得太小。

## 8. 每座島增加至三隻自主活動動物

目前部分動物種類在不同島重複，例如魚、企鵝、鯊魚。

請改成：

- **每座單元島配置三隻可見且會自主活動的小動物。**
- S01–S15 的特色動物種類不重複。
- 同一座島上的三隻動物可以是相同代表物種的不同個體，也可以搭配不同小動物。
- 不要求 45 種不同物種，但必須讓不同島嶼的特色動物容易區分。
- 三隻動物不可全部做同步動畫。
- 可以有不同體型、顏色及動畫相位。
- 不阻擋 NPC、Lecture 小屋與文字標籤。
- 未開放島仍保留動物動畫。
- Video-only 模式仍保留全部動物。
- 動物全部不可與玩家互動。

## 9. 效能要求

因為這次要增加裝飾、移動 NPC 及三倍動物數量，請特別注意效能。

- 遠景降低動物與 NPC 動畫更新頻率。
- 近景時仍保持流暢動畫。
- NPC 及動物不能被錯誤合批為靜態幾何。
- 共用材質與幾何，減少 Draw Calls。
- 適合的大量小物件採用 InstancedMesh。
- 保留既有 GPU 資源釋放機制。
- 避免新增重度粒子、後製效果及大型外部模型。
- 報告 12／15 島總覽與單島聚焦的 FPS、Draw Calls、Triangles。
- 軟體 GPU 數據必須與真實 GPU 效能分開報告。

- Agent A：各主題島的靜態裝飾與地貌精修。
- Agent B：NPC 自主移動與停止互動機制。

不同 Agent 不得同時修改 src/scene.js、src/main.js、src/style.css 等共用核心。必要時先建立獨立模組，再由主 Agent 整合。
