## 2. 主要開發目標

將目前「中央學院 + S01 森林島」擴充成完整的 3D 課程群島。

- 中央學院主島固定存在。
- 支援 S01–S15，最多 15 座單元島。
- 預設數位電子學使用 S01–S12。
- `course-config.json` 的 `totalUnits` 決定實際顯示數量。
- 其他課程若設定 15，才顯示 S13–S15。
- 所有島嶼位於同一個連續 Three.js 世界。
- 使用同一個斜上方 OrthographicCamera。
- 不新增學生角色、移動控制或物理引擎。

**本階段最重要的成果是：讓整座群島看起來豐富、精緻、有生命力，而不是只有 15 個不同顏色的幾何物件。**

### 地形要求

- 每座島必須有明顯不同的地貌輪廓。
- 不得只是對同一地形替換顏色。
- 島體有厚度、不規則海岸線、自然岩坡與局部高低差。
- 避免規則方柱、六角柱、垂直擠出的平坦地形。
- 保留童話、Low-Poly、色彩豐富的微型模型風格。
- 適當加入瀑布、池塘、植被、岩塊、漂浮裝飾等元素。
- S01 原有設計及鯊魚動畫須保留，不要無故重做。

可以使用共用的程序化幾何、場景元件及固定主題 Preset，以減少重複程式碼。但不同主題必須有真正可辨識的視覺差異。

## 4. 群島布局與橋樑

請設計中央主島與最多 15 座單元島的完整空間布局。

### 布局原則

- 中央學院是視覺與導航中心。
- 周圍島嶼以自然、略帶不規則的方式分布。
- 島嶼之間保持足夠間距。
- 不可相互重疊，避免 3D 投影下的前後遮擋。
- 可以使用多圈或分支式布局，不必強迫全部島嶼形成機械式圓環。
- S01–S12 的預設布局與 S01–S15 的布局都要有良好的總覽構圖。
- 橋樑可以從中央主島分支，也可透過相鄰島嶼串接，但應形成清楚合理的群島連接網路，避免橋梁大量交叉。

### 橋樑風格

沿用 Phase 1 已完成的微拱木橋風格。

- 木橋、繩欄、木柱與微弧橋面。
- 橋樑兩端要自然銜接島嶼地形。
- 不應出現橋樑懸空、穿過岩石或在海面突然中斷。
- 橋樑只負責視覺串接，不需要碰撞、導航或互動。

### 未開放島的橋樑 — 已正式定案

**所有已規劃島嶼的橋樑都保持完整。**

已開放島：
- 橋樑暢通，不顯示柵欄及鎖牌。

未開放島：
- 在靠近單元島的橋樑入口加上一座可愛的小木柵欄。
- 柵欄上有清楚的鎖定標誌。
- 島嶼仍保留原本繽紛色彩與動物動畫，不要把整座島變成灰色。
- 可查看島的外觀，但不可開啟 Lecture 或 Quiz。
- 點擊時顯示「Sxx 尚未開放」。
- 未來 Manifest 開放該島時，柵欄與鎖牌自動消失。

不要為了柵欄新增複雜物理或通行系統。

## 5. 全域縮放與聚焦

沿用 Phase 1 已驗證的滑鼠操作方式。

### 全域總覽

- 初始畫面可以看到中央學院及全部已規劃的單元島。
- 自動根據 totalUnits = 1–15 計算合理的取景範圍。
- 預設 12 島不能被裁切。
- 15 島模式也必須能夠完整觀看。
- 島嶼標籤 S01–S15 應清楚且盡量避免重疊。
- 全域時不需要顯示所有 Q01–Q05 小標籤，避免畫面雜亂。

### 單島聚焦

- 點擊單元島或其標牌，鏡頭平滑移動至該島。
- 可以繼續使用滾輪放大，看清 Lecture 小屋、NPC 與動物。
- 返回總覽時，平滑縮回完整群島。
- 聚焦時避免鄰島或橋樑遮擋重要內容。
- 若原有相機最大縮放限制無法適應 15 島，請合理調整相機參數，不要直接破壞原本雙島操作。

必須確保縮放後的畫面仍有清楚的互動目標，而不只是場景被放大。

## 6. NPC 與課程模式

維持既有設定：

- `quiz`
- `video-only`

### Quiz 模式

- 每座單元島預留 4–5 位 NPC 的合適配置位置。
- NPC 頭頂有明顯的 Q01–Q05 標示。
- 使用彩色服裝及清楚的人物造型。
- 不得被建築、樹木或小動物長時間遮擋。
- Phase 2 可以使用安全的 Demo NPC 視覺資料。
- 不得提前實作或虛構正式題庫。

### Video-only 模式

- 完全不生成 NPC 模型。
- 不顯示 Q01–Q05 標籤。
- 不保留 NPC 的可點擊目標。
- Lecture 小屋、動物及島嶼場景仍正常顯示。

### Lecture 小屋

每座島都需要一座明顯的 Lecture 小屋，依照島嶼主題變化外觀。

例如冰雪島為冰晶小屋、糖果島為甜點屋、火山島為岩石研究站。

本階段仍只需要點擊視覺原型，不實作正式 YouTube 清單。

## 7. 小動物與環境動畫

這是本專案最重要的特色之一。

所有小動物都是**不可互動的自主環境裝飾**。

- 不接受點擊、餵食或控制。
- 不干涉 NPC、Lecture 或相機操作。
- 使用簡單、流暢且可愛的循環動畫。
- 允許荒誕、不符合自然常理的行為。
- 每座島具有自己的代表性動物。
- 不同動物動畫的時間與相位要錯開。

除了動物，也可以加入適量的環境動畫，例如流水、風車、樹葉、花草、浪花及發光植物。

但不要為了增加動畫而犧牲一般筆電的效能。

## 8. 效能與程式架構

目前使用：

- Node.js 24
- Vite
- Three.js WebGLRenderer
- Vanilla JavaScript / CSS

請保持既有技術架構。

由於場景將從 2 座島增加至最多 16 座（含中央主島），請注意：

- 共用幾何與材質，適合時使用 InstancedMesh。
- 避免過多 Draw Calls。
- 遠距離島嶼降低動畫與細節成本。
- 必要時使用 LOD 或可見性裁切。
- 避免對全部島嶼同時使用高成本陰影與粒子特效。
- 正確釋放不再使用的 GPU 資源。
- 保留快速回到群島總覽的能力。
- 任何效能優化不得破壞已驗收的 S01 美術與互動。

請使用實際測試資料報告 FPS、Draw Calls、Triangle Count 與 GPU/瀏覽器測試限制，不要只根據 npm build 成功就宣稱效能良好。

## 9. Manifest 與 Demo 的範圍

保留既有 `course-config.json` 與 `assignments/manifest.json` 格式，不新增第二套發布清單。

Phase 2 應先完成島嶼開放／鎖定的視覺狀態及判斷邏輯，並使用目前已載入的 Manifest 作為正式狀態來源。

正式 Repository 預設：

`{"schemaVersion":1,"units":[]}`

不得自行公開任何課程。

可以建立明確隔離的本機 Demo，模擬不同開放進度，例如已開放 S01–S04，其餘仍鎖定，用以驗證柵欄顯示、鏡頭與群島布局。

Demo 不得改動正式發布清單，也不可透過正式 production URL 的 query parameter 啟用。

在 Phase 2 中，只完成視覺狀態、聚焦與鎖定提示。真正的 Lecture 資料載入與 Quiz 判答仍留待 Phase 3、Phase 4。

## 10. 測試與驗收

至少驗證以下情境：

1. totalUnits = 1、12、15 都能正常產生群島。
2. 12 島與 15 島總覽都沒有漏島或明顯裁切。
3. S01–S12 各具有明顯不同的地貌。
4. S13–S15 只在 totalUnits 包含它們時出現。
5. 橋樑完整連接島嶼，沒有明顯懸空或穿模。
6. 未開放島的入口顯示柵欄與鎖牌，已開放島沒有。
7. 未開放島無法開啟 Lecture 或 Quiz 內容。
8. 滑鼠縮放、平移、島嶼聚焦、返回總覽正常。
9. Quiz Demo 有清晰 NPC；Video-only 完全沒有 NPC。
10. 所有小動物自主活動，不接受使用者互動。
11. 一般 1366×768、1920×1080 螢幕構圖合理，窄視窗不造成嚴重 UI 重疊。
12. 既有 Phase 1 測試全部通過。

執行：

- `npm test`
- `npm run build`
- `npm run test:smoke`
- `npm run test:browser`

請新增必要的自動化測試與代表性瀏覽器截圖。

至少提供：12 島全域總覽、15 島總覽、火山島、冰雪島、糖果島、未開放島橋樑柵欄、Video-only 模式。
