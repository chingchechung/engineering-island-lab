Internally batch whale static parts in local frames using read-only optimize helpers if useful; do not bake movable parts or shader water. Shared geometry/materials; no external textures/models or heavy particles. snapshot reports sea time and whales [{id,position,spouting,...}]. Expose route metadata needed to test offshore clearance. No changes to any existing file, docs, settings, Git or PR.

## Agent B: noninteractive visitor system

Own only `src/world/visitors.js`, `src/world/visitor-navigation.js`, `test/visitors.test.js`.
Export `createVisitors({academy:Object3D, records:Map, seed=73})` -> `{root:Group, visitors:Object3D[], update(seconds), snapshot(), navigation:...}`. Main calls it after existing question NPC motions/safety are initialized and before static batching. Each record is {root,terrain,house,top,preset:{id,...},unlocked,link:{from,to,curve,bridge},npcs,safety}; local geometry and world matrices are still available. Academy has `getObjectByName('coast-and-cliffs')` and is an always-accessible transit hub ONLY when an open unit exists. Spawn/dwell only on unlocked unit islands; 0 unlocked -> 0 visitors, otherwise about 3–8 total based on open count. Disconnected open islands may roam but MUST NOT traverse a locked parent; use only edges whose both ends are allowed (academy transit allowed). All groups attach to returned world-coordinate root, not unit roots. Mark decoration=true/animated=true, no action, no Q labels or numbers; original small tourists visibly distinct from question NPCs (~0.6–0.7 their height).

Maintain a small deterministic ground waypoint grid/graph or comparably simple routing: actual land height and obstacle checks before batching; paths around buildings/water/rock, safe shore approaches, then exact existing bridge curve centerline at deck height. Avoid diagonal corner cutting, teleporting, water and bridge rails. Freeze CPU-only geometry/matrix references if batching removes sources. Routes can cross academy between open islands, visit multiple islands and return; dwell/wander on arrival before next trip. Start first trips early enough to observe in a normal Demo. Dynamic distance/yield around question NPC roots and other visitors prevents sustained overlap; never pause or otherwise mutate question NPCs. Pure deterministic absolute-time update with bounded dt/substeps, no DOM/camera/input state. Main invokes near at frame rate, overview about 6Hz. Snapshot array entries include {id,unitId,phase,from,to,position,...}; during a bridge crossing include from/to so integration can verify both allowed. Expose enough navigation metadata for route validation. Reuse existing primitives/optimize read-only, keep draw calls modest, moving limbs local. No full game physics/nav engine. No changes to shared source/tests/configs/docs/Git/PR. Ask main before API changes.
