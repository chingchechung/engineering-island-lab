# Engineering Island Lab — 分階段執行與教師驗收 v0.1

**原則：每一 Phase 單獨 branch + Draft PR，完整測試後交老師用 Windows Chrome/Edge 驗收；未獲授權不進下一 Phase、不合併、不部署、不發 Release。**

## Phase 0 — 現況檢查 / 架構 / 開發規範

- 查核既有初始化的 Vite + Three.js 專案、Git/Node 版本、當前 branch、套件及腳本；先跑 npm test/build。
- 補齊 `AGENTS.md`、`Plan.md`、README 及設計與資料契約文件；建立明確的模組切分（相機/群島布局/地貌工廠/動畫/互動拾取/UI/資料驗證）。
- 確認 `base: './'`、`public` JSON 複製策略、禁止自動發布教材，建立純測試 fixture。
- **交付**：基準報告、架構圖/目錄草案、回歸命令。

## Phase 1 — 3D 世界與 S01 的可點擊視覺原型（本次實作到這裡就停）

**目標不是把教育功能都做完，而是先確認整體視覺方向和相機操作真的可用。**

- 單一 3D 世界：中央學院主島與 S01 森林島，斜上方正交視角；自然不規則島體、有厚度的岩崖、草地、海面、樹、花、瀑布/小高差。避免正立方體/規則六角柱。
- 具備平滑滾輪縮放、拖曳平移、點擊 S01 聚焦與『返回總覽』，click/drag 區分、視角不裁切。中央學院可見『數位電子學』字樣。
- S01 一座可點擊 Lecture 小屋與 Q01–Q04 明顯 NPC（僅以本機 Demo fixture 提供安全的點擊提示或占位 Modal，**不用真實題庫連結**，正式公開 manifest 保持 `units: []`）；一隻在草地跳動的可愛鯊魚，其動畫不會被玩家影響。
- 模組結構已可在 `video-only` 中完全不生成 NPC。單元總數/模式設定必須有基本解析與單元測試；可以只繪製 S01，**尚未完成的 11/14 座島要在報告中明確標明缺口**。
- **驗收**：Windows Chrome/Edge 能看到自然 3D 島、清楚標籤、小島不是幾何柱；滾輪/拖曳/點擊/返回無誤觸，鯊魚持續動，video-only Demo 不見 NPC，npm test/build 通過。
- **停止點**：Draft PR 交付教師確認美術與操控；未通過不要直接生成另外 14 座。

## Phase 2 — 群島完整版與主題多樣性

- 定義 15 種預先編寫的地貌 preset（S01–S12 正式主題、S13–S15 預留），各有不同剪影、色彩、植物、動物、建築。
- 根據 `course-config.totalUnits` 顯示 1–15 島、全域相機 fit、中央島、島名標籤；未開放島可見但鎖定；不超過總數的島才出現。
- 依距離/焦點控制遠景 vs 聚焦細節和動畫負擔；海面、花草、風車等動態精修。視覺上不是同一個島換顏色。
- **驗收**：12 島與 15 島都能縮小看全圖；放大島嶼可辨識不同地貌，未開放島不可讀取課程內容；Windows 瀏覽器效能可接受。

## Phase 2.5 — 日夜點燈與相機環繞（教師追加授權）

- Phase2已經Windows驗收、PR #2合併後，從main建立feature/phase-2-5-day-night-camera-orbit。
- Day精確保留，Night冷色環境搭配學院／全部小屋窗光、六主橋燈及15主題發光。1.25秒切換，有限實例化批次，僅一個聚焦無陰影局部光，無Bloom。
- 單一正交相機水平連轉、仰角25–70度；左拖旋轉、右拖／Shift左拖平移；逐角度fit、窄畫面深度及海面覆蓋、聚焦保方向、返回標準總覽。
- 保留NPC／Modal、模式、鎖定與所有自主生命；標牌避讓及多指取消不誤點，不改布局／地貌／正式JSON。
- **驗收與停止**：完整測試、日夜與旋轉截圖、同條件效能及Windows步驟，只建立唯一Draft PR #3後等教師，不進Phase3／合併／部署／Tag／Release。詳見PHASE_2_5_BRIEF及PHASE_2_5_ACCEPTANCE。

## Phase 3 — Lecture 清單及教材發布

- 實作 `course-config.json`、`course-videos/Sxx.json` 載入與驗證、Quiz/Video-only 模式切換、Manifest 釋出清單、已開放/鎖定島狀態。
- Lecture 小屋點擊開可滾動 Modal；任意數量影片，單一清單且順序不變，全部另開 YouTube，Modal 不自動關閉，Esc/close 可用。
- README 編寫「Notion PDF → AI 抽取每週影片 JSON → 驗證 → 教師審核 → 上傳影片 JSON → 最後更新 Manifest」流程與 Prompt。
- **驗收**：Sxx 可有 1/4/10 部影片、無英文影片、不同順序；不排序、不額外開 3D 場景；鎖定單元無互動。video-only 沒有 NPC/Quiz。

## Phase 4 — 舊題庫 v1/v2 的 NPC Quiz 整合

- 參照已驗證的 Maze/City Lab JSON 規則與測試，透過明確單獨的 JS 模組實作/移植（不重寫成另套不相容規則）。
- Q01–Q04/可選 Q05 NPC，點選後題目影片、選項、錯答重試、答對後解答影片及 Google Forms 門檻。
- 單元上限擴充至 15，但應將既有 Python 出題 GUI 的 S13–S15 支援記錄為獨立待辦，不碰另一個 repo，除非教師授權。
- **驗收**：schema v1 / v2、4/5 題、v2 任一接受答案判對、完整 Form 解鎖；video-only 連 Quiz 程式 UI 都不出現，未載入題庫絕不偷切模式。

## Phase 5 — 完整回歸、封裝及正式發布準備

- Windows 實機 Chrome/Edge，包含校方 Apache 子目錄部署情境；測套件相依、404/MIME、JSON 更新順序、再載入後個人狀態清除。
- 有安全的打包/驗證工具（必要時），正式包不得自動攜帶教師私密題庫草稿、測試檔、憑證、學生資料。
- 完整第三方素材/字體/音效授權清單、README 學期操作與問題排解。若要標 Tag/Release/上傳站台，必須事先另行取得教師明確授權。

## 每個 Phase 的 Draft PR 必須提供

- 概述做了什麼、沒做什麼；主要變更檔案/模組；`npm test`、`npm run build` 與瀏覽器測試的實際結果；遇到的限制。
- 教師可複製的本機啟動/驗收命令、至少 5–10 條肉眼/操作驗收清單，並標明尚未實測的事項。
- 提供代表性截圖或具體視覺驗收方式（若工具允許）；不能僅靠單元測試宣稱「美術風格已驗收」。
- 等待教師回覆後才合併或進入下一階段。
