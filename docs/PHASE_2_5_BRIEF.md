# Part A — 白天／夜晚光照系統

## 三、整體美術目標

教師提供的參考網站為：

https://gujin-edu-island.pages.dev/

教師也提供了該網站的白天及夜晚截圖。

本次請借鏡其視覺表現，而不是複製原始程式或模型。

### 白天畫面

- 明亮天空與清晰的日光。
- 藍綠色、具有輕微流動效果的海面。
- 建築、花草、岩壁與木橋具有自然陰影。
- 維持現在已經通過驗收的繽紛童話 Low-Poly 風格。

### 夜晚畫面

- 海面變成柔和的深藍色。
- 環境光改為偏冷色的夜間光照。
- 中央學院、Lecture 小屋、橋樑、路燈與部分植物出現溫暖或夢幻的點燈效果。
- 夜晚仍能清楚看見島嶼、NPC、動物與建築。
- 明顯呈現冷色環境與暖色燈光的對比。

**重要：夜晚不能只是降低整張畫面的亮度或套用深藍色濾鏡，必須真的有建築、橋樑及環境裝飾的點燈效果。**

整體應呈現「白天是繽紛童話群島，夜晚是溫暖點燈的奇幻群島」。

## 四、Day / Night 切換方式

請在網頁右上角加入一個小型切換控制。

建議：

- 白天顯示太陽圖示。
- 夜晚顯示月亮圖示。
- 點擊後在 Day / Night 間切換。
- 使用約 1–1.5 秒的平滑過渡。
- 切換期間相機、NPC、動物及背景旅人繼續正常運作。
- 不需真實時間同步。
- 不需自動日夜循環。
- 頁面重新載入後預設 Day。
- 不必儲存使用者的選擇。
- 不能增加會大量遮擋 3D 畫面的設定面板。

按鈕應提供適當的 aria-label，且可使用鍵盤操作。

## 五、日夜光照與天空

### Day

保留目前的 HemisphereLight、DirectionalLight、色調映射與陰影風格。

不應為了夜晚模式而明顯破壞已驗收的白天效果。

### Night

建議使用：

- 深藍色或柔和藍綠色天空。
- 較低強度的冷色環境光。
- 柔和月光方向光。
- 適量冷色補光，避免物體完全變黑。
- 少量近景局部照明。
- 暖色 Emissive Material 表現窗光、燈籠與裝飾。

必須妥善處理目前的 ACES tone mapping、sRGB 輸出、陰影材質及共享材質。

不能為了切換夜間效果，破壞其他島嶼的材質或造成 GPU 資源洩漏。

## 六、建築夜間燈光

### 中央學院

請加入：

- 學院窗戶的暖黃色發光效果。
- 大門附近的小型照明。
- 可視情況加入少量裝飾燈。
- 從群島總覽仍能辨識中央學院的位置。

### Lecture 小屋

S01–S15 每座小屋都應有夜間燈光。

建議：

- 窗戶發光。
- 門口或屋簷下的小燈。
- 不同主題的小屋可有不同的燈具造型。
- 不要擋住 Lecture 標牌與點擊區。

在 Quiz 模式及 Video-only 模式中都需要顯示。

### 木橋

這次非常重視橋樑夜景。

中央學院向外放射的六條主幹木橋，應有適量暖色小燈或燈串。

可以是：

- 木柱頂端小燈。
- 部分橋樑上的懸掛燈串。
- 少量暖黃色燈籠。

燈光密度需適當，不要讓所有木橋變成整條高亮光帶。

從全域總覽時，應該能感受到六條橋樑向不同島嶼延伸的點燈效果。

請延續既有系統：

- 白天海面使用目前的明亮藍綠色。
- 夜晚海面轉為較深的藍色。
- 夜間保留原本的流動波紋。
- 可以增加少量月光反射或柔和亮面。
- 鯨魚與噴水在夜間仍應能辨識。

## 九、燈光效能限制

**不得為每一個燈籠及窗戶都建立一個具有陰影的 PointLight。**

優先使用：

- Emissive Materials
- 共享或實例化的發光幾何
- 少量、經過位置與可見性管理的實際光源
- 聚焦島嶼才啟用的局部照明效果
- 不需要昂貴陰影的裝飾燈

可以使用簡單的光暈幾何，但不應預設引入重度 Bloom Post-processing。

如果後處理會顯著降低一般 Windows 筆電的 FPS，請選擇較低成本的替代方案。

# Part B — 3D Camera Orbit

## 十、相機改造目標

目前 `CameraRig` 採用固定約 42° 俯視角度的 OrthographicCamera。

教師希望使用滑鼠拖曳自由旋轉 3D 群島，從不同方向欣賞：

- 島嶼與岩壁。
- 建築正面、背面與側面。
- 橋樑布局。
- 瀑布與植物。
- 小動物與巡遊鯨魚。

請改成支援 Camera Orbit，但保留原本的正交投影及微型模型美術風格。

**只旋轉相機，不旋轉整個 Three.js 世界。**

## 十一、滑鼠操作規格

正式操作統一如下：

| 操作 | 功能 |
|---|---|
| 左鍵單擊 | 選擇島嶼、Lecture 小屋或 NPC |
| 左鍵按住拖曳 | 旋轉相機 |
| 右鍵按住拖曳 | 平移畫面 |
| Shift + 左鍵拖曳 | 平移畫面 |
| 滑鼠滾輪 | 放大／縮小 |
| 返回總覽 | 恢復完整群島的標準視角與取景 |

請保留既有 click / drag 位移閾值。

只要手勢已被判定為旋轉或平移，滑鼠放開時絕對不能觸發 Lecture 或 NPC 的點擊事件。

滑鼠移動到 CSS2D 標籤或按鈕時，也不能發生不正確的事件穿透。

## 十二、旋轉角度

### 水平方向

- 支援完整 360° 環繞。
- 可以連續旋轉，不受 360° 單圈限制。
- 旋轉操作應平滑。
- 適度使用阻尼或平滑內插，但不要造成操作延遲過大。

### 垂直方向

建議限制為離水平面約 25°–70° 的觀察仰角。

- 不允許上下翻轉。
- 不允許鏡頭穿過地面。
- 不允許相機進入海底。
- 不需要第一人稱或自由飛行模式。

### 初始角度

保留原本 Phase 2 已驗收的斜上方約 42° 視角，作為標準方向。

## 十三、相機旋轉中心

### 群島總覽

- 相機圍繞整座群島中心旋轉。
- 使用者可觀察整體放射狀橋樑與島嶼排列。
- 旋轉時不能因原本的 fit 計算只適合固定角度，而大量裁切外圍島嶼。
- 請依目前旋轉角度重新評估正交相機的可見範圍。

### 單島聚焦

- 相機圍繞目前聚焦的單元島旋轉。
- 可以觀察島嶼背面及不同角度的地形。
- 從 S01 切換到 S02 時，相機平滑移動至新目標。
- 優先保留使用者當下的旋轉方向。
- 不要每換一座島就突然跳回固定方向。

### 返回總覽

按「返回總覽」時：

1. 平滑移動至群島中心。
2. 恢復原始斜上方約 42° 視角。
3. 恢復原本標準的水平方向。
4. 自動調整縮放，顯示所有已規劃島嶼。

此操作必須在 totalUnits = 1、12、15 時都正常。

## 十四、既有 CameraRig 整合

請先評估擴充 `src/camera.js` 的現有 `CameraRig`，包括：

- target / goal
- focus / reset
- zoom / zoomGoal
- pan
- resize
- fitHeight
- update

可以改為具有 Azimuth / Elevation 的相機控制架構。

若決定使用 Three.js OrbitControls，必須整合既有平滑聚焦與 pointer gesture，避免出現兩組同時競爭相機控制權的事件系統。

請選擇較單純、可維護且與現有架構相容的方案，不必為了使用現成控制器而重寫整個導航系統。

## 十五、旋轉後的標籤與互動

這是本次相機改造最重要的相容性要求。

旋轉相機後，以下功能必須仍然正確：

- 島嶼 S01–S15 標籤的位置及可讀性。
- CSS2D 頭頂 Q01–Q05 標籤跟隨 NPC。
- 島嶼標籤的避讓演算法。
- Lecture 小屋 Raycasting。
- 移動中 NPC 的模型及標牌點擊。
- 點擊 NPC 後暫停，關閉 Modal 後恢復。
- 鎖定柵欄與島嶼點擊。
- 相機旋轉、平移、縮放與返回總覽。

請特別檢查：

**旋轉 180° 後，由原本背面露出的建築與樹木，不可造成 NPC 或 Lecture 無法正常使用。**

如果從特定角度真的發生遮擋，可以優先保留可操作的 CSS2D 標籤，並在必要時改善物件拾取或局部構圖。

同時注意不要因為從背面觀看，讓本來正確的 Q01–Q05 選取操作變成其他 NPC。

## 十六、Modal 與相機控制隔離

Lecture、NPC 或操作說明視窗開啟時：

- 不允許旋轉相機。
- 不允許平移相機。
- 不允許縮放相機。
- 滾輪只捲動 Modal 內容。
- Esc 與關閉按鈕維持正常。
- NPC 的 pause / resume 維持正常。
- 背景動物、鯨魚與小旅人可以繼續活動。

保留 Phase 2 已驗收的大字體閱讀版面。

## 十七、手機與觸控相容性

本次以 Windows 11 Chrome／Edge 滑鼠為主要驗收環境。

但不得破壞既有的觸控操作。

- 原有單指操作至少不能退步。
- 多指操作不得被誤判為 NPC 點擊。
- 不能因滑鼠旋轉功能而導致手機版完全無法使用。
- 若加入雙指縮放，需要獨立測試；不要求本階段一定完成完整觸控手勢系統。
